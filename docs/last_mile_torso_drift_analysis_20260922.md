# RBY1M torso「自漂移 / 自穿插」根因分析与修复

**2026-09-22｜回答：last-mile P0/P1 的 torso 自漂移，与 LLM planner 预检里的 torso 自穿插，有无共性原因。**

## 0. 结论

**没有同一个因果根因，但共享同一个结构性缺陷：两处验收阈值都定在 RBY1M 模型自身噪声底之下。**

| | last-mile 的 torso 自漂移 | LLM planner 的 torso 自穿插 |
|---|---|---|
| 物理域 | 动力学（有限刚度位置伺服 + 底盘阶跃） | 运动学几何（IK 构型 + 相邻连杆网格） |
| 触发量 | 底盘 waypoint 阶跃 → 惯性载荷 | IK 把 `torso_4` 顶到关节上限 +0.524 |
| 实测幅度 | 0.033–0.055 rad | 0.047–0.24 mm 穿透 |
| 受伤关节/连杆 | torso 六个关节（torso_0 最大） | `link_torso_2` ↔ `link_torso_4`（名义间隙 15 mm） |
| 失败判据 | 每 4 ms 检查峰值 ≤ 1e-3 rad | 任何新增接触即失败（0 容差） |

两者既不同域、也不互为因果：预检是纯运动学（`mj_forward` + 接触几何），不含动力学，动力学挠度不可能出现在预检里；反过来，预检里的亚毫米穿透也不会造成 1e-3 rad 的关节偏转。共享的是同一件事——**RBY1M 的 torso 是模型里最"软"的一段**：运动学上它有 6 个自由度承担冗余，动力学上它 kp=4000 却要扛整个上半身的惯量，几何上相邻连杆壳间隙只有 15 mm。任何"torso 应精确保持不变"的理想化断言都会在这段上失败。

同一病理在本仓库已经出现第三次：P1-E02 里被判 `collision` 的两条，是底盘蹭门框/台面的 **0.43–0.63 mm** 穿透，与 LLM planner 的 0.047–0.24 mm 属同一类网格擦碰。

## 1. torso 自漂移的机制

### 1.1 复现方法

只加载 `robots/rby1m/rby1_v1.2_site_control.xml`（无场景），按 molmospaces 的 spec 路径打开 gravcomp（`spec.body("robot_0/").find_all("body") → body.gravcomp = 1.0` 后 `compile()`），把姿态设成 `RBY1Config.init_qpos`，静止收敛后给底盘一个阶跃指令，逐 2 ms sim step 记录各关节组 `|qpos - ctrl|`。

> 注意：**`body_gravcomp` 只能在 compile 期设置**。编译后直接赋值 `model.body_gravcomp[:] = 1.0` 不会生效（`qfrc_gravcomp` 仍为 0），会把重力下垂误当成挠度。用 spec 路径时 `qfrc_gravcomp` 精确抵消 `qfrc_bias`。

### 1.2 复现结果与 P1 实测逐位吻合

施加 P1 首个 A* waypoint（Δx=0.010 m、Δy=0.015 m、Δyaw=0.1686 rad）后 20 ms：

| 组 | 独立模型 | P1-E01 实测 |
|---|---|---|
| torso | 1.169e-3 rad | 1.1702e-3 rad |
| 左臂 | 2.86e-4 rad | 2.77e-4 / 2.27e-4 rad |
| head | 6.39e-6 rad | 6.02e-6 rad |

三组数字都对上，说明场景对这项动力学几乎无贡献。

### 1.3 不是重力下垂

同样配置下不给任何指令（静置），torso 偏差是 **1.08e-18 rad**。gravcomp 生效时位置伺服把上半身稳稳托住，不存在静态下垂。

### 1.4 是阻尼瞬态，不是永久偏移

| t | torso 偏差 |
|---|---|
| 20 ms | 1.169e-3 rad |
| 120 ms | 4.26e-3 rad（峰值） |
| 400 ms | 1.97e-3 rad |
| 800 ms | 6.6e-5 rad |
| 2.9 s | 4.9e-6 rad |

完全恢复，无永久偏移。位置伺服在做它该做的事。

### 1.5 对指令阶跃严格线性

| Δyaw | torso 峰值 |
|---|---|
| 0.01 rad | 2.43e-4 |
| 0.05 rad | 1.21e-3 |
| 0.1686 rad | 4.09e-3 |
| 0.3 rad | 7.28e-3 |
| 0.5 rad | 1.21e-2 |

线性关系是惯性弹性响应的标志性特征：底盘阶跃 → 加速度 → 关节惯性力矩 → 挠度 τ/kp。

### 1.6 真实的 waypoint 比第一印象大一个数量级

E01 因为逐 4 ms 判据在第一个策略步就中止，只暴露了首个 waypoint。从 E02 存下的轨迹统计真实量级：

| 场景 | 步数 | max Δxy | p95 Δxy | max Δyaw | p95 Δyaw |
|---|---|---|---|---|---|
| E02 全部 | 1–87 | 0.154 m | 0.126–0.143 m | 56°[^wrap] | 10–21° |

[^wrap]: max Δyaw 里混有跨 ±π 的角度环绕伪影（如 357°），按 p95 看真实量级是 10–21°。

即 A* 每 100 ms 下发 Δxy≈0.13 m、Δyaw≈10–20° 的阶跃（隐含 ~1.3 m/s，远高于 0.8 m 截断半径暗示的 0.3 m/s）。按线性关系外推 0.14 m ≈ 0.13/0.018 × 3.77e-3 ≈ 0.027 rad，与实测 0.033–0.050 rad 吻合。

按真实幅度重跑独立模型（Δxy=0.13 m、Δyaw=15°/步、30 步）得到导航期间 torso 峰值 **0.0545 rad**，与真实环境一致。

### 1.7 为什么 torso 最明显、且 10 条同时失败

torso 的六个关节承载整个上半身（两个大臂 + head + 胸部连杆）的惯量，力臂最大、kp 只有 4000；head 质量小且质心接近转轴（4e-6 量级）；臂的自身惯量小于躯干。所有场景共用同一机器人模型、同一收拢姿态、同一控制频率和同一段导航方式，所以"底盘首次加速 → 上半身惯性耦合"是共同机制，10 条在相近时刻越界。

### 1.8 指令层其实一直是满足的

`max_nonbase_command_drift` 在 E01 和 E02 的每一条里都是 **0.0**。原因是结构性的：`Robot.update_control` 只对 action 里出现的 move group 调 `set_target`，其余控制器走 `elif not controller.stationary: set_to_stationary()`；而 `synchronize_navigation_start` 结束时已把所有控制器置为 stationary，此后 `update_control({"base": ...})` 不会再碰它们。

也就是说，把"固定"理解为"没有向非底盘关节发送新指令"，**当前实现一直满足**；只有把"固定"理解为"实际 qpos 永不偏离 1e-3 rad"，才不可能满足。

## 2. 修复：把判据分层

### 2.1 设计

`nav_adapter.execute_navigation` 的非 base 关节判据改为三层：

1. **指令不变式（导航期间，0 容差，硬失败）**：任何非 base 控制器目标被改写即 `controller_error: nonbase_command_changed`。这是"固定"的精确含义，且无数值噪声。此前该量只被记录、未被强制。
2. **瞬态上限（导航期间，护栏）**：物理 qpos 偏差超过 `nonbase_joint_transient_tolerance` 即失败，默认 **0.2 rad**。
3. **稳态偏差（handover，保留冻结的 1e-3 rad）**：导航 `completed` 后把底盘就地停住（`controllers["base"].set_to_stationary()`，其 `noop_ctrl` 返回当前实际底盘位姿），稳定 `end_controller_settle_steps` 个控制步，再按原判据检查物理 qpos——这才是交给评价器的姿态。

新增 `settle_before_handover()`，稳定期间不做任何新指令，仍执行与导航期间相同的非法碰撞/目标位移/非有限状态/瞬态上限检查；逐控制步记录偏差曲线进 artifact 供审计。

### 2.2 参数取值依据（全部来自实测，不是拍的）

| 参数 | 值 | 依据 |
|---|---|---|
| `nonbase_joint_drift_tolerance` | **1e-3 rad（原值不动）** | 冻结值，现在可满足：停稳 3.0 s 后实测残差 1.06e-5，余量 100× |
| `nonbase_joint_transient_tolerance` | **0.2 rad** | 合法弹性挠度实测最大 0.0578（独立模型）/ 0.0502（E02）；真故障量级 ≥ O(1) rad。3.5× 余量 |
| `end_controller_settle_steps` | **150（3.0 s）** | 停稳后约 1.0 s 回到 1e-3 以下、2 s 到 1e-4；3 s 留足余量 |
| `endpoint_se2_tolerance` | 0.05 m（原值不动） | 稳态判据接入后端点改在停稳后测量，实测 0.030 |

### 2.3 验证

**单元测试**：P0+P1 共 27 项通过。新增覆盖：稳态偏差分类、瞬态上限与冻结阈值分离、控制器目标被改写时的 0 容差判定。

**端到端**：同一 ten-episode 试点跑三轮，每轮只改判据参数：

| 轮次 | 判据 | 结果 |
|---|---|---|
| P1-E01 | 每 4 ms 峰值 ≤ 1e-3 rad | `controller_error` 10/10（全在第一个策略步） |
| P1-E02 | 瞬态上限 0.05 rad + 停稳 1.0 s 后判 1e-3 | `collision` 2、`no_path` 3、`controller_error` 5、有效 A **0** |
| P1-E03 | 瞬态上限 0.2 rad + 停稳 3.0 s 后判 1e-3 | `collision` 2、`no_path` 3、`completed` **5**、有效 A **5**，P2 gate **open** |

E02 → E03 同一条 H191 #2 的对比，可以精确分离"窗口长度"这一个变量：

| | E02（1.0 s 窗口） | E03（3.0 s 窗口） |
|---|---|---|
| 端点 SE(2) 误差 | — | 0.030 m ✓（阈值 0.05） |
| 稳态偏差 | 2.1302770518295657e-3 ✗ | 1.0627e-5 ✓（阈值 1e-3，余量 100×） |
| settle 曲线 1.0 s 处 | — | 2.1302770518295657e-3 |

E03 的 settle 曲线在 1.0 s 处的值与 E02 报告的稳态值**逐位相同**，交叉验证了两次运行之间唯一的变化就是窗口长度；冻结的 1e-3 rad 判据本身没有被修改。

**确定性复查**：E03 被独立跑了两遍（第二遍只是因为协议名常量写错而重跑），10 条的全部数值字段与 150 点 settle 曲线**逐位相同**，满足 P1 的"同状态同种子结果重复一致"。

### 2.4 修好之后暴露出的其余失败（不在本次修复范围）

逐 4 ms 判据把 E01 的 10 条全部冻死在第一个策略步，掩盖了下游的真实结果。判据分层后剩下的 5 条失败：

- **`no_path` 3 条**：A* 自身的 `failed_to_return_for_replan`（"Replanning requested after returning to the previous N waypoints due to failure to progress"，距离卡在 0.13–0.19 m）。这是真实的导航失败，不是判据伪影。
- **`collision` 2 条**：底盘蹭门框 **0.63 mm**、蹭台面 **0.43–0.56 mm**。都是亚毫米网格擦碰，与第 0 节说的 LLM planner 自穿插同属一类。

第 2 类如果按同一原则处理（把不可消除的模型噪声从硬失败里分离出来），P1 的接触判据需要一个 ~1 mm 的容差；但这会改变"有效 A"的定义与 headline 数字，属独立决定，**未擅自改动**，只在此记录证据。

## 3. 未做的事

- **没有改 XML / 提高 torso kp**：那会改变模型动力学，影响所有历史与未来对比，而且真实机器人的位置伺服本来就有有限刚度。
- **没有对底盘指令做插值或斜坡**：会改变导航行为（协议要求沿用现有朝向逻辑与截断参数），而且按实测的线性关系，把 100 ms 的阶跃摊到 5 个控制步只能把峰值降约 5 倍——真实幅度下是从 0.055 降到 ~0.011 rad，仍比原判据高一个数量级，治标不治本。
- **没有给 P1 的接触判据加容差**：那会改变"有效 A"的定义与 headline 数字，属独立决定，留待确认。
